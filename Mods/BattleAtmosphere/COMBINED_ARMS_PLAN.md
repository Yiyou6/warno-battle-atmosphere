# 运输、兵种搭配与战术方案及实装

2026-11-06。状态：用户已接受方案并授权实施。沿用已获用户认可的 preview.4 基准。用户特别修正交替掩护：多数部队要持续前进，可以慢一些，不能在后方干坐着。后续协同采用持续跟进、不同推进步长与射击时机，不采用固定停住半数兵力的轮换模式。实现与验收状态逐项记录，不能把批准方案写成已经落地。

## 目标与经济前提

用户反馈：步战车有时在远后方卸载；采购偏向步兵与步战车，坦克不足；希望增加战术变化。最高难度、双倍资金，AI 每分钟至少 1000+ 为用户给定基准。设计必须考虑持续高收入、大量并发购买和增援，不靠让部队在后方等完整编组控流。不改用户收入设置，不把用户估计写成精确实测。

保持各可用兵种有实际作用，保留师/卡组的真实库存约束；建议按角色缺口与在场有效兵力配置，而非所有单位类别严格等数量。昂贵坦克、飞机必须获得可实现的购买机会，不能永远被便宜步兵抢走余额；资金增加也不能只放大原有偏科。

## 1. 连续的机械化步兵任务

候选 A：只改运输距离阈值。改动小，但请求运输与卸载不是同一环节，且全局阈值容易同时伤害安全下车、补给或重新乘车；不采用为主方案。

候选 B：按前线区段管理“运送 → 定点下车 → 步兵推进/车辆支援”。推荐。

- 以分配区段的实际前沿、道路可达性和已确认的威胁信息选择下车带，不使用全军最前单位或地图固定坐标；首轮可把友军接触前沿后约 200–500 米作为可调试验范围，不能保证所有地形都适用。
- 每辆运输车分配独立下车点，计入其他车辆的到达预约，避免把原有单位堆改造成卸车场堆。
- 运送时保持车辆与载员绑定，步兵不能提前获得独立徒步路线。受到直接攻击、前路不可达或车辆失去继续运送能力时允许应急卸载/改点。
- 确认卸载完成后，步兵接续本区段任务；有战斗能力的步战车在附近提供支援，再逐步推进。无武装卡车不使用步战车支援职责。
- 已经提前下车的单位，只有剩余徒步路程明显过长、有可用配对车辆且重新上车确有收益时才考虑重载；加迟滞与失败退出，避免上下车循环。

必须先确认载员 ID 关系、原生定点卸载指令、任务独占与应急行为，再扩大载员接管。不能为了实现此方案拆掉 preview.4 的载员安全过滤。

## 2. 面向缺口的采购

候选 A：固定轮流买每一类。简单但会在缺卡、库存耗尽或没有实际用途时卡住/浪费资源；不推荐。

候选 B：只提高坦克任务优先级和预算。可作为受控对照，但可能再次挤掉防空、炮兵和补给；不作为完整方案。

候选 C：基础角色保障 + 当前缺口 + 有期限的预算保留。推荐。

- 将坦克、步兵、武装运输/支援车、侦察、反坦克、防空、炮兵、航空和补给分开统计用途。步兵购买附带的步战车必须计入已有数量与费用，不能再被当成完全缺失的车辆支援重复补买。
- 采购看当前有效在场兵力、在途/已排队单位、损失、卡组库存和角色缺口，并记录实际支出；仅看购买数量会低估昂贵坦克与飞机。
- 给坦克等昂贵角色保留有限、可到期的采购额度，便宜单位仍可从其他额度持续出兵。有钱但被任务上限挡住时调整对应任务，不能以多次廉价替代掩盖坦克长期缺席。
- 用滚动时间窗检查每类有货且确有用途的兵种是否长期没有采购机会；无库存、无可用卡、已经过量应明确跳过，不让全军等它。
- 公共宽战线职责负责新兵去哪里，采购层负责缺什么。不能为搭配强制把已在场的部队重新拉回后方凑齐队伍。

实时读取资金、库存、排队请求以及发起合法采购尚未接入当前桥接。第一步应把原生任务配置的偏向与预算逐项核对，结合出生/采购事件记录；不能声称写了预算公式就会在游戏执行。

## 3. 战术候选

建议在现有宽战线调度上增加按区段决策的状态层，而非每次更新随机换一棵大树。示意评分因素是任务收益、可用兵种、可信威胁、到达时间、拥堵与切换成本。每个战术都有触发条件、执行反馈、退出条件和短暂稳定期；失败只调整局部，不让全线停止。

| 战术 | 触发与玩家能看到的行为 | 耦合与退出要求 |
| --- | --- | --- |
| 步坦协同推进 | 步兵在林地/建筑方向推进，坦克负责适合车辆的射界，卸载后的步战车就近支援；防空跟随所保护方向 | 需地形/掩护与支援任务能力；维持各自间隔，不绑成一个密集团。缺某兵种时降低计划规模，不原地等齐 |
| 随队掩护（按用户修正） | 多数部队持续前进；已经接敌的单位使用原生火力动作，附近未接敌车辆缩短单次推进距离，后方增援继续赶上 | 不安排固定轮换停住半数兵力。缩短路段不等于修改车辆最高速度；实际机动节奏须观察 |
| 炮火准备后推进 | 某区段受阻，炮兵/烟幕支援相关方向，突击队利用支援窗口前进 | 需原生合法支援请求、目标与落点验证。无炮/无弹/无效等待则换方案，其他区段继续作战 |
| 正面牵制、邻接侧翼绕进 | 正面正在接战，左右相邻区段具有可行机动路径时从侧方推进 | 先核实敌军可见性与威胁；当前“向外展开”不冒充已识别敌人并包围。避免两翼过远脱节 |
| 局部突破后扩张 | 某区段推进较顺，有限后续兵力补入，先头分出力量扩宽突破口两侧并承担要点任务 | 限制突破口容量；不能全军追着一个成功目标重新挤成团。相邻区域继续保持覆盖 |
| 受挫换路、邻区反击 | 某处反复无进展/损失显著，调整本地路径与兵种；己方区段受压时邻区就近支援 | 反击必须以可信态势为依据。支援方保留必要覆盖，不同时抽空多段；前沿单位不因重规划退回后方集结 |

本轮先组合运输任务链、采购纠偏、持续跟进与局部战术分支，随后接炮火准备和真正的敌情驱动侧翼。用户已授权实施；每项必须单独记录接入程度。

## 联合验收与实现顺序建议

1. 增加运输事件/载员配对与采购来源观察，区分自定义控制、原生卸载、强制卸载，以及没买到坦克与坦克早早损失。
2. 一条机制一次接入，先独立原生回归，再复用用户最高难度/双倍资金普通对局。与 preview.4 的同场景表现比较。
3. 卸载记录距所属区段前沿的距离、异常提前卸载原因、下车后的步行距离及车辆支援；不只验证下车命令成功。
4. 采购记录分时段支出、单位类型、在途和库存，覆盖坦克/步兵/支援型卡组；双方仍有持续交战且不无脑送兵。
5. 各战术记录触发、有效动作、完成/失败和退出，检查是否出现左右往返、订单打架、后方闲置、密集卸车或全线长时间等待。
6. 维持 preview.4 已获认可的实际宽度、两翼连续推进、据点集中后疏散。任何改动造成这些优点消失，应回退该机制并查因。

## preview.5 本轮实现与边界

运行代码已完成，安装与最终验证状态见 `Development/combined-release.json`（该回执产生前不能称为已安装）。

- **运输链**：原生载员关系、定点卸载和应急卸载已接通。友军正在交战时按附近接触前沿选点；没有接触时采用友军推进位置与公开地图中线的保守估计，不能把该估计称作精确敌我接触线。候选卸载带在估计前沿后 250/400/550 米；不同车辆卸载预约至少相隔 160 米，逐一检查车辆和乘员的导航类型。接近目的地时若前沿已明显移动，最多调整三次，避免无限追赶。载员保持绑定；交战或长时间无进展允许应急下车。卸载后步兵接续宽战线，有武器车辆短程跟进。普通移动的运输安全过滤保留。
- **采购纠偏**：普通组和合成组预算增至 450，坦克组增至 500；普通组提前放置坦克槽，新增单坦克、可跳过的 360 点采购任务，并替换三个重复普通增援任务中的一个。库存为空不阻塞普通推进；保持原有防空、炮兵、飞机、补给与侦察任务。70 默认卡组静态审计中两套没有普通坦克卡，不能凭空产生卡外坦克。170 个普通坦克描述中，32 个超过旧 200 点上限，最高 345 点。该部分为原生任务采购纠偏，**尚不是实时资金/队列/库存驱动的完整缺口采购器**；不保证固定兵种比例。`FORCE_MIX` 统计在场角色和首次观察数量，不是实际扣款购买事件。
- **战术状态**：依据本区段/邻区友军真实交战、各段推进差异和路线失败反馈选择持续展开、后方赶上、接触推进、随队支援、邻接侧翼推进、突破延伸、受阻换路。除原有可行性/边界限制外，新分支均产生正向目标；不新增“半数原地等待”的轮换安排。侧翼偏移短期保持，避免每次回调左右摇摆。各单位仍受统一阵位预约与核心限额约束。这里的侧翼来自友军接战信号，不能冒充已识别敌阵并完成合围。
- **尚未纳入本轮**：自动重新乘车、按建筑/林地掩护质量布阵、实时预算保留、直接调度炮兵/烟幕、敌情驱动包围。原有原生炮空支援继续工作。这些需要进一步接入数据与下令接口，不能用新增状态名宣称完成。

离线测试覆盖身份保护、载员互斥、运输失败释放、正常卸载后持续投入、死亡不算成功送达、卸载点预约、接触/侧翼/绕行正向目标与后方赶上。原生验证分别检查实际运输、长时间连续增援、真实交战及冷启动；用户普通最高难度、双倍资金对局的运输观感与兵种比例另验。资金设置完全沿用用户配置。

额外饱和边界：合成模型一次在 6 列密集纵队中放入 1000 辆武装载具、没有交火，60 秒内 preview.5 只向 270 辆发出路线（preview.4 同条件 263）；240 秒分别为 536/538。此极端输入仍未通过快速解堵目标，不能宣称任意兵力密度都能立即展开，也不能把它等同于真实的每分钟 1000+ 收入。结果和对照保留在 `Development/combined-1000-stress.json`。普通规模持续增援、交战回归另作验收，不用此压力模型替代真实对局，也不删除失败结果。
