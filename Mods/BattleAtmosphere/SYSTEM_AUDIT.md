# AI 系统分析与实验记录

日期：2026-11-06。版本：0.1.0-experimental。

**本文保留早期静态审计及九文件草稿的历史记录，并非最终修改决策。当前以 [遭遇战系统设计](SKIRMISH_DESIGN.md) 为准；只面向最高难度遭遇战。后方长期囤积大量无实际用途的可用兵力是整体验收的否决项。**

第一版实际实现见 [IMPLEMENTATION](IMPLEMENTATION.md)。新证据已确认全局常量进入 GFX/Skirmish 事务；炮兵原有三个极难覆盖未含最高难度；部分旧反坦克标签不存在。下表“0.1 处理”为历史，不是 0.2.0-test1 的当前参数。

所有设计服从根目录 README 中的核心体验目标。下文“确认”仅指静态文件事实；尚无本项目的原版对局基线，不能把嫌疑机制写成已证实的运行时原因。

## AI 链条

当前可见链条为：难度／模式选择策略 → 阶段与转换 → 任务生成与扩展 → 采购预算和编组 → 通道／目标分配 → 地面、炮兵、空袭等任务执行 → 威胁、撤退和补给处理。

这些阶段是引擎已有机制。任务列表的顺序表达优先级，不等于严格按时间执行的剧本；将炮兵排在主攻前，不能保证每次都完成炮火准备才推进。

## 逐环节发现

| 编号 | 静态事实或待验证假设 | 0.1 处理 | 验证风险与下一步 |
|---|---|---|---|
| BA-01 调度与预算 | 主攻原预算 600，多个昂贵地面／直升机任务排在协同支援炮兵之前；普通交战列表有多次静态防御请求 | 重排普通以上三个策略，主攻预算 420，后续扩展也安排支援炮兵 | 优先级并非执行时间表；确认早期支援不会挤空地面兵力，缺兵种时不会阻塞 |
| BA-02 空地请求 | `BasicAirstrikeSupport` 原标签 `Avion_Assaut`、`Chasseur_Bombardier`、`Bombardier` 在静态单位定义中均为 0 匹配 | 换成 `Avion_Bombardier`、`Avion_AT`、`Avion_Napalm`，静态匹配分别为 198、43、22；这是全单位数据计数，不是每个卡组可用量 | 仍需确认运行时请求语义、可用飞机、目标限制与武器投放；不排除引擎动态标签 |
| BA-03 炮兵链条 | 独立炮兵与 `Artillery_Support` 分属不同任务；后者已有 `IsSupport` 协调配置；原本通常出现在靠后的追加列表 | 提前协同支援炮兵，新增扩展任务，适度降低开火门槛 | 监测弹药和补给耗尽、对低价值目标浪费火力；统计炮击与地面进攻是否同区同时间 |
| BA-04 防空角色失真 | 专职防空池为随机价格选择，包含防空直升机，并追加坦克、普通步兵、支援车等通用兜底项 | 专职池限制为地面防空，按较低价格选择；提前防空任务 | 无防空卡组或防空耗尽时是否跳过而不阻塞，需要单独测试 |
| BA-05 无效闲置 | 原任务表包含多次静态防御；通道、目标、预算与兵种不匹配都可能产生闲置，但没有运行时证据证明单一原因 | 减少重复静态任务，保留据点守备、侧线进攻、盟友增援和补给 | 不把合理预备、集结或缺弹休整计为故障；记录具体单位的任务与闲置时长 |
| BA-06 运兵车 | `CanSelectTransportUnits=false`；有武装运输车标签，BMP 等还可能同时有支援车辆标签 | 侧线池增加武装运输车候选；不贸然全局开启运输车再选择 | 该开关可能影响已载人车辆或运输任务；卸载后是否可重新分配尚未验证，不标记修复 |
| BA-07 装甲纵队 | 主攻池原本先列两个最昂贵坦克槽位，步兵靠后；主攻默认带 `LaunchAsSoonAsPossible`；主攻排除 Filler 通道，坦克的通道占用权重只有步兵一半 | 重组主攻池，尝试默认批次生产；开放通道；坦克占用权重 0.5→1.0、通道预留门槛 15→10 | 取消 ASAP 是否导致攒兵过久、Filler 路线是否适合车辆，都需要测试；局部队形与底层寻路仍未解决 |
| BA-08 直升机过早消耗 | 除专门的直升机任务外，主攻、普通攻击、合成攻击等池也含战斗直升机，单纯删除开局直升机任务会遗漏这些来源 | 从混合地面攻击池移除战斗直升机；普通以上开局不安排专门直升机任务，交战后保留一个槽位的专门任务 | 这是阶段与编组约束，不是已实现“发现特定威胁后才出机”的新触发器；高开局资金下仍需查漏 |
| BA-09 持续攻防 | 原劣势阶段有连续三个主攻请求；全局撤退后返回等待 7.5，生命撤退阈值 0.3；补给与撤退阈值有明确联动 | 劣势阶段保留补给、侦察、防空、守备与支援；返回等待 15，生命撤退 0.35，生命补给 0.55 | 防止延长等待造成战线空洞；不保证每局都高损失，观察攻势能否受阻后恢复 |
| BA-10 飞机盘旋 | 飞机攻击类型含内部 `TBombAttackStrategyDescriptor` 等对象；所见数据没有完整的目标失效／重新规划／超时返航状态机 | 修正上游请求标签与门槛，前移攻击任务；保留原版飞行与投放参数 | 收集机型、弹药、目标类型、视野、威胁区域和盘旋时长；区分正常待命与任务执行失败。未修复声明 |
| BA-11 步兵师对装甲师 | 原主攻前列偏向昂贵装甲；三种步兵进攻池没有明确的步兵反坦克槽位，坦克／车辆兜底较多 | 主攻将反坦克、防空放在可选坦克之前；步兵池显式安排反坦克、防空、侦察，预算 160→220 | 兵种存在不等于有效交战；开放地形与城镇／树林分别检验，禁止用单一地图胜率判定所有师 |
| BA-12 全局搭配 | 购买顺序、槽位顺序、价格选择、任务预算和后续扩展共同决定实际兵种分布 | 主攻控制装甲数量，兼顾侦察、步兵、反坦克、防空；支援任务有独立位置 | 可选槽位仍可能因预算或卡组被跳过，不能声称每支队伍必然齐全 |

## 源文件定位

- 策略选择：`GameData/Gameplay/Skirmish/IASkirmishDescriptors.ndf`。普通用 Generic，困难用 Hard，极难与最高难度共用 VeryHard。票券经济与突破模式有独立覆盖，不能笼统称为全部模式已重写。
- 阶段和任务顺序：`GameData/Gameplay/Skirmish/Strategies/{Generic,Hard,VeryHard}SkirmishStrategy.ndf`。
- 攻击编组和生产方式：`GameData/Gameplay/Skirmish/SkirmishMacros/SkirmishAttacks.ndf`。
- 防空与守备：同目录 `SkirmishDefenses.ndf`。
- 空地请求与补给：同目录 `SkirmishMisc.ndf`。
- 空袭接收类型与威胁门槛：同目录 `SkirmishAirstrike.ndf`。
- 炮兵支援、开火门槛、射后转移：同目录 `SkirmishArtillery.ndf`。
- 通道、威胁、撤退和机会空袭：`GameData/Gameplay/Constantes/IAStratConstantes.ndf`。
- 静态单位标签依据：`GameData/Generated/Gameplay/Gfx/UniteDescriptor.ndf`，本版只读取、不修改。
- 飞行执行层：`GameData/Gameplay/Unit/AirplaneConstantes.ndf`，本版只读取、不修改。
- 补给与撤退联动依据：`GameData/Gameplay/Skirmish/TestIA/SkirmishMacrosOnlyForTestAuto.ndf` 的 `Supply_TestAutoOnly` 注释。

## 尚未完成的系统分析

1. **实战任务追踪**：区分策略不派任务、生产未完成、单位分配失败、目标失效、寻路失败和正常休整；需要对局或调试界面证据。
2. **运输车生命周期**：装载、卸载、运输任务结束和战斗任务接管；开启选择开关前验证不会把载人车辆单独送走。
3. **局部接敌展开**：现有全局阵形参数也影响玩家，不能把改宽度当作已修复 AI 的战术展开；需要专门场景。
4. **师与地图适配**：分析真实卡组的单位可用量、运输费用、反坦克射程与地形覆盖，区分师本身的劣势与 AI 使用失误。
5. **最高难度实际策略入口**：核对遭遇战所用经济／部署规则是否覆盖默认 VeryHard 选择；不开展其他模式或低难度的独立审计。
6. **阶段转换与恢复**：原劣势阶段未见返回普通阶段的显式转换；先记录，不在不明比分条件语义时随意加入循环。
7. **氛围表现**：本版未修改音效、特效、残骸持续时间和压制数值；先验证现有战斗机制的组织方式是否改善体验，再决定表现层改动。

## 判定标准

首先看玩家能否感知有原因的出兵、有效的火力支援、反复的攻守争夺和累积代价。统计数据用于解释体验：不能把更多飞机在空中、更多炮弹落地、更多单位死亡自动等同于更好的战场氛围。
